# Distribution surfaces

- Search ownership files: `/google557b38af0966bb0e.html` and `/BingSiteAuth.xml`. Keep exact bytes and case. Once production serves them, the owner must finish verification in Google Search Console and Bing Webmaster Tools, then submit `https://www.statwindow.app/sitemap.xml`. Adding files does not itself verify or index the site.
- Public, crawlable `/how-to-play.html`, `/embed.html`, `/media.html` and `/contact.html`; all canonical URLs are in the sitemap. Challenge and referral URLs keep their game behavior and declare the homepage canonical, so query variants stay out of the sitemap. Vercel sets `X-Robots-Tag: noindex` on preview deployments. Check that preview responses include it and the branded production domain does not.
- Media library: `/media.html` and `/media/manifest.json`. Download three screenshots, two short clips, two labeled demonstration scorecards, and brand files. The gameplay assets use the evergreen untimed teaching questions. The scorecards contain fictional scores and are generated by the same renderer the game uses. Small static previews load before the full-size images or videos.
- Embed: copy the HTML on the page, test in a separate-origin host on desktop and mobile, including storage restrictions and new-tab fallback. No guarantee of cross-site native sharing.
- Referral measurement: see MEASUREMENT.md. Use recognized source tags. No paid analytics or added dependencies.

## Release checks
Run repository gates and independent review at the integrated SHA. Verify both root token files return exact bytes and HTTP 200 on branded production, crawlable pages/links and assets work, mobile widths and focus, embed on a separate origin, analytics receipt and privacy opt-out. Do not change launch date or official content. Do not publish before required release gates pass.

### Capture a real gameplay asset
Run `npm run build` and `npm run preview`, then run `node scripts/media/capture.mjs` with Playwright Chromium installed. Set `MEDIA_PORT` for a different preview port or `MEDIA_CHROMIUM` for a local Chromium executable. The script uses fresh browser contexts, blocks requests to other origins and telemetry and score endpoints, and verifies the teaching ID and exact prompt before capture. It saves 20 fitted gameplay PNG candidates and two demo card PNGs to a unique `build/media-review/capture-*` directory. The card fixture only exists in the capture script and uses synthetic rounds without loading a player’s history.

Set `MEDIA_VIDEO=1` to also record a hit and a miss from the first-play tutorial. These use Playwright’s recorder and system FFmpeg with H.264 to produce silent 1080 × 1920 MP4s. The videos start after the practice question opens and show real bracket drags, the lock, the reveal and the ball’s progress on the court. Navigation overlays and date-specific controls are omitted from captures.

The capture manifest leaves all new candidates pending. Review the selected stills and full clips for clipping, readability, pacing, and spoilers before copying them to `public/media/`. Create small WebP previews for published assets and update the asset manifest and page with the source, dimensions, format, alt text and approval. Keep the files static and review them in the integrated browser build before release.

### Contact and feedback
Contact uses ordinary email links. Completed results offer feedback and question reports with only the puzzle date, position and public question ID. The address is visible on the contact page for manual copying. Secondary public links appear on Home and Results, outside timed rounds.

### Publisher configurator
The responsive snippet includes a visible new-tab attribution link; height is bounded to 600–1,400 px and the optional maximum width to 320–1,440 px. The iframe keeps its fluid width on narrower publisher layouts. The width/height preview is deliberately illustrative, not a live iframe, so opening the configuration page cannot auto-resume a timed game or contaminate official events. The separate-origin Playwright fixture exercises the actual generated iframe against the isolated local game. Clipboard permission failures select the code for manual copying. WordPress and Ghost instructions reference their official help pages, including WordPress.com plan limitations and Ghost email limitations. The embed channel is fixed; no per-publisher identifier or new tracking. No CSP/header changes.

### Install and external browsers
The install disclosure explains how to open the game in a regular browser and warns that history may be separate. Embedded results link to the game in a new tab. If a desktop browser rejects its native install prompt, the install button opens browser-menu and bookmark guidance.
