# V5.2 Day 1 cutover simulation

Date run: 2026-11-27, on branch `statwindow/v5-2` (PR #33). `LAUNCH_DAY` is `'2026-11-30'` in `src/engine/launch-config.ts` and was not changed. Nothing here touched production or a Vercel environment.

## How

- **Browser:** `e2e/launch.spec.ts` against the isolated `VITE_LAUNCH_PREVIEW=1` build (`dist-launch-test`, never deployed), on system Chrome, desktop (1440×900) and mobile (Pixel 7):
  `LAUNCH_E2E=1 E2E_PORT=4184 npx playwright test -c playwright.chrome.config.ts e2e/launch.spec.ts`
  Clocks are pinned with `page.clock.setFixedTime` or, for the open-tab case, `page.clock.install` + `runFor`. `/api/scores` is stubbed to 503 so no score leaves the browser.
- **New block, "committed Day 1 (LAUNCH_DAY 2026-11-30)":** these cases use no `?launch-preview=` parameter, so they exercise the committed launch day exactly as production will. The older cases in the file use a synthetic launch day (`2027-01-10`, `2026-11-28`) through the preview parameter and still pass.
- **Server:** `server/api.test.ts`, block "Day 1 cutover: the score API season matches the client". It builds the context with `contextFromEnv` (the production path) and posts real verified runs for Nov 29, Nov 30 and Dec 1.
- **Unit:** `src/engine/season.test.ts`, `src/engine/launch-config.test.ts`, `src/engine/weekly.test.ts`, `scripts/season-check.test.ts` (already present; re-run).

## Limitations

- The real native share sheet (iOS/Android `navigator.share`) can't be driven by Playwright; only the clipboard path (desktop Chromium) and the selectable-text fallback are checked. WebKit was not run here (no bundled browsers in this environment).
- The production build guard (`vite.config.ts` reading production's `/launch.json`) and `npm run season:check` were not run against the live deployment; their logic is covered by `launch-config.test.ts` and `season-check.test.ts`.
- Real wall-clock behaviour (a device sleeping through midnight, OS clock drift) is approximated by `visibilitychange` and the 30 s interval; a frozen-then-resumed tab was not simulated beyond the interval firing.
- Score percentiles were stubbed off in the browser; season partitioning is proved only in the server unit tests (memory store), not against Upstash.
- Activation is still only **scheduled**. It counts as observed once someone opens production on 2026-11-30 and sees "Game 1" (record it in `docs/LAUNCH.md`).
- The first case in `e2e/launch.spec.ts`, "unset launch config preserves live beta numbering…", no longer runs with an unset config (2027-01-09 is an `s1` day now that `LAUNCH_DAY` is committed). It still passes and still proves an in-season link keeps its score, but its name is out of date.
